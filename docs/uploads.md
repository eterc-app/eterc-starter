# Files and uploads

This project uses a three-step upload pipeline with a provider-neutral storage
contract. The browser sends bytes directly to the storage service when the
provider supports presigned uploads; the Next.js process only validates the
request, records metadata, and verifies the object afterwards.

## Deployment policy

| Deployment target (`ET_DEPLOYMENT_PROVIDER`) | Local disk | Requirement |
| --- | --- | --- |
| `local` | allowed | Local development / single persistent host |
| `docker-vps` | allowed (volume) | Single node. MinIO is recommended |
| `ubuntu` | forbidden | Object storage required |
| `other` | forbidden | Object storage required |
| `vercel` | forbidden | Object storage required |

`assert_storage_policy()` runs at server startup and in `/api/health`. A
misconfigured server fails closed instead of writing uploads to an ephemeral
filesystem.

## End-to-end flow

```
1. POST /api/xhr/media/asset_init   { kind, name, content_type, size, folder, visibility }
   → validates extension, size, quota, CSRF, admin session
   → creates cms_media_assets row (status=pending, expires in 15 minutes)
   → returns { asset, upload: { url, method, headers, fields } }

2. PUT <upload.url>
   → presigned S3/R2/MinIO/GCS/Azure/Supabase URL, or
     /api/media/uploads/local (signed upload token), or
     /api/media/uploads/relay (server relay for Vercel Blob / UploadThing)

3. POST /api/xhr/media/asset_complete { asset_id }
   → HEAD/stat the object, verify size and content type
   → magic-byte validation, sharp metadata + pixel limit, malware scan hook
   → SHA-256 checksum and duplicate reuse
   → image variants (thumb 480, sm 960, md 1600, lg 2400) as WebP
   → marks the asset ready (or quarantined)
```

The upload token for the local and relay routes is an HMAC-signed, 15-minute,
single-purpose token. It is issued only after the admin session and CSRF checks
in `asset_init`. The byte routes are excluded from `src/proxy.ts` so Next.js
never clones or buffers the request body.

## Storage layout

| Object | Location |
| --- | --- |
| Local public | `public/uploads/<folder>/<yyyy>/<mm>/<uuid>.<ext>` |
| Local private | `data/private-uploads/<folder>/<yyyy>/<mm>/<uuid>.<ext>` |
| Local variants | `<same folder>/variants/<uuid>-<variant>.webp` |
| Remote public | provider key `<folder>/<yyyy>/<mm>/<uuid>.<ext>` |
| Remote private | same key with `visibility=private`, served by signed URLs |
| Temporary stream files | `data/tmp/uploads/*.part` (renamed atomically) |

Private local objects are **not** served by `/uploads`. They are available only
through `GET /api/media/download/<key>`, which checks the session and the
asset owner/admin role before streaming or redirecting to a signed URL.

## Metadata

Registry tables (created by `ensure_cms_schema` / `remote-ddl.ts`):

- `cms_media_assets` — status, provider, key, size, MIME, checksum, dimensions,
  folder, visibility, owner, expiry, soft delete.
- `cms_media_variants` — thumb/sm/md/lg keys, dimensions and byte size.
- `cms_media_audit` — init/complete/delete/download/deduplicate events.

The legacy `data/settings/media_library/index.json` and the `public/uploads`
tree are imported once (`media_registry_v1` migration marker). Existing
`/uploads/...` URLs keep working.

## Configuration

```dotenv
# Optional path overrides (tests, containers with separate volumes)
ET_DATA_DIR=./data
ET_UPLOADS_DIR=./public/uploads

ET_MEDIA_MAX_IMAGE_MB=12
ET_MEDIA_MAX_FILE_MB=25
ET_MEDIA_MAX_BYTES_PER_USER=0      # 0 = unlimited
ET_MEDIA_MAX_FILES_PER_USER=0
ET_MEDIA_UPLOADS_PER_HOUR=120
ET_MEDIA_MAINTENANCE=1             # hourly pending-upload cleanup
ET_UPLOAD_SCAN=off                 # off | best-effort | required
# ET_UPLOAD_SCAN_URL="http://scanner:3310/scan"
# ET_UPLOAD_SCAN_TOKEN=""
```

The scanner receives the raw bytes (`application/octet-stream`) and must return
`{ "clean": true }` or `{ "clean": false, "message": "..." }`. `required` makes
an unavailable scanner a hard failure; `best-effort` records the asset as clean
with an audit note.

## Provider requirements

- S3/R2/MinIO: bucket CORS must allow `PUT` from the app origin, plus `GET` and
  `HEAD` for image verification. Keep the bucket private; serve reads with
  signed URLs unless a CDN is configured through `AWS_S3_PUBLIC_BASE_URL`.
- MinIO in Docker: Caddy proxies `storage.<domain>` to `minio:9000`, and
  `AWS_S3_ENDPOINT` is set to that public URL. Without a domain, the generated
  bundle falls back to `http://127.0.0.1:9000` and presigned URLs only work from
  the Docker host's browser.
- Supabase Storage: use a private bucket; `createSignedUploadUrl` and signed
  reads are generated by the adapter.
- Google Cloud Storage: the service account needs `storage.objects.create`,
  `get`, `list` and `delete` on the bucket.
- Azure Blob: the connection string must allow container read/write; SAS URLs
  are generated for upload and download.
- Vercel Blob / UploadThing: no presigned upload protocol in this adapter, so
  the server relay streams (or buffers within the limit) through the app. Use
  them only when direct upload is not a hard requirement.

## Operations

- **Pending cleanup**: `cleanup_pending_uploads()` runs hourly from
  `src/instrumentation.ts`; pending assets older than 30 minutes are removed
  from storage and soft-deleted.
- **Reconciliation**: `POST /api/xhr/media/asset_reconcile` (admin) compares the
  registry with the provider listing and reports orphans/missing objects.
- **Manual cleanup**: `POST /api/xhr/media/asset_cleanup`.
- **Quotas**: enforced at `asset_init`; rate limits use the active cache
  provider (per-process for the memory cache, shared for Redis/Valkey).
- **Backups**: Docker + local tars `public/uploads`; remote providers must use
  bucket versioning/lifecycle. Private local objects live under `data/`, which
  is already in the app data backup.

## Validation matrix

| Check | Images | Documents |
| --- | --- | --- |
| Extension allowlist | jpg/jpeg/png/gif/webp | pdf/doc(x)/xls(x)/ppt(x)/csv/txt/rtf/zip/tar/gz/mp3/wav/mp4/webm |
| Content sniff | sharp + magic bytes | magic bytes per extension |
| Dimensions | max 12000 px, 40M pixels | n/a |
| Size | `ET_MEDIA_MAX_IMAGE_MB` | `ET_MEDIA_MAX_FILE_MB` |
| Malware scan | optional/required | optional/required |
| Checksum | SHA-256, deduplicated | SHA-256, deduplicated |

## Deprecated endpoint

`POST /api/media/upload` remains as a compatibility shim for one release. It
buffers the multipart body and is limited by `MAX_MEDIA_BYTES` /
`MAX_FILE_UPLOAD_BYTES`; new clients must use `asset_init`/`asset_complete`.
