# Generated modules

Flo writes complete Next.js modules into this directory:

```
src/modules/generated/<module_name>/
  <Module>.ts              controller (extends @/engine/controller)
  <Module>_model.ts        model (extends @/engine/model)
  views/
    manage.tsx
    create.tsx
    show.tsx
    delete_conf.tsx
    not_found.tsx
    search_modal.tsx       only when a searchable property exists
    PerPageSelect.tsx
    index.ts               registers the module's views
  <module_name>.sql        one-shot schema (removed after a successful run)
  manifest.json            metadata used to rebuild ./index.ts
```

`./index.ts` is regenerated by Flo after every successful generation. It
statically imports each generated view map (registering it with
`@/engine/views-registry`). It also exports:

- `generatedModules` — metadata keyed by module name.
- `generatedControllerLoaders` — lazy `() => import(...)` loaders keyed by
  module name.

## One-time wiring (required)

Do this once after installing Flo. Flo never edits these shared files, and no
further edit is needed when new modules are generated.

### 1. `src/engine/registrations.ts`

Import the generated loaders and spread them into `controllerLoaders`:

```ts
import { generatedControllerLoaders } from "@/modules/generated";

export const controllerLoaders: Record<
  string,
  () => Promise<{ default: ControllerCtor }>
> = {
  // ...existing loaders...
  ...generatedControllerLoaders,
};
```

### 2. `src/modules/views.ts`

Add a side-effect import so the generated view maps are registered at boot:

```ts
import "@/modules/generated";
```

That is the entire registration contract. Generating another module only
rewrites `src/modules/generated/index.ts`; neither shared file changes again.

## Runtime behaviour

- A generated controller is addressed as `/<module_name>/<method>` exactly
  like a hand-written module (for example `/tasks/manage`).
- Generated views are addressed as `<module_name>/<view_file>` and are reached
  through the admin template used by the generated controller.
- Next.js only bundles imports that exist at build time. After generating a
  module, wait for the dev server to recompile (or restart it / rebuild the
  app) before opening the new module.
- If a generation fails after the files are written but before the index is
  rebuilt, call Flo's `rebuild_generated_index` path by re-running generation
  with a new name, or rebuild `index.ts` from the existing `manifest.json`
  files.

## Safety rules

- Generated module directories are never overwritten. Flo refuses a module
  name that already exists under `src/modules/generated` or `src/modules`.
- Writes go to a staging directory first and are moved into place with one
  rename, so a half-written module is never visible.
- Do not edit `./index.ts` manually; it is overwritten on the next generation.
